# Skills map for CS2

Which skill runs at which stage, and what each one is for. Maintained as we go rather than decided
once. Searched for skills outside the enabled set on 2026-08-27 and found none, so this is the
working set.

## Pass 1, extract
- `affinity-diagram` : governs the method. Data points pulled before any grouping, tagged with
  source, no predefined categories.
- `context-engineering` : mechanics of working a corpus larger than context without losing detail.
- `research-repository` : how the extraction is stored so it stays findable and does not have to be
  redone. Should have been used when the corpus was first built.

## Pass 2, cluster
- `affinity-diagram` : bottom-up clustering, coverage check across all 154 sources.
- `research-synthesis` : run alongside as a second method over the same material. Two methods catch
  what one misses.

## Pass 3, themes and insights
- `affinity-diagram` : insight statements, frequency, intensity, single-source flags.
- `research-synthesis` : themes, segments, prioritisation.
- `jobs-to-be-done` : if the themes point at belief rather than logistics, this is the frame.

## Pass 4, story
- `case-study` : format selection and beats.
- `jobs-to-be-done` : available as a narrative format in its own right.
- `design-rationale` : connecting decisions to user needs and principles in the decision sections.
- `design-impact-reporting` : the ending. This is the skill for communicating contribution where
  there are no metrics, which is our situation.
- `business-design` : hiring manager framing, defending decisions in the language of value.
- `ux-copy` and `humanizer` : every line.

## Build
- `artifact-design` : before writing the page.
- `information-architecture` and `user-flow-diagram` : the diagrams, as real artifacts rather than
  invented forms.
- `visual-hierarchy`, `typography-scale`, `layout-grid` : layout.
- `artifact-diagramming` : diagram legibility.
- `design-critique` : self-review before showing Chadwick.

## Standing
- `verification-before-completion` : guard against declaring things locked, done or verified before
  they are. Directly addresses a repeated failure in this project.
