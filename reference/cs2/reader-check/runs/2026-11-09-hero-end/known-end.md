# What the reader already knows before the ending (final copy, 9 Nov)

Built from reference/cs2/review-2026-11-07/final-copy.md, page in order, every block before the ending. K1 is
only what all three new hero versions say, so the ending is judged against any of them.

K1. Mondai's AI writes each user a curriculum for the tech career they choose, and it can take months. Most users don't have the same hours free every week, so the author designed a weekly framework that turns the curriculum into weeks each user can finish, planned around the hours they can give. Mondai hasn't launched; the case study shows the reasoning rather than results.
K2. Mondai shows a target date (set by the plan) and a pace date (where progress points), like CareerFoundry. A connected calendar suggests where work fits; the plan runs without one. The home screen shows only this week's work. The plan sets the goal and the user decides where in their day the work goes.
K3. The Growth Journey is five Pathways, one at a time in order; each Pathway holds Action Items, the pieces of work, grouped into Focus Areas.
K4. The Growth Journey has its own page with the journey's target, pace and progress, kept off the weekly screen.
K5. Each Pathway has its own page with its Action Items in order, locked ones included, its target and pace and Focus Areas.
K6. The Action Hub is the screen of this week's Action Items, opened nearly every day; each week opens with an AI written headline and paragraph; items are finished in order and only the top one, marked Active, can be checked off.
K7. The AI writes each Action Item as text on a page of ten kinds of plain text containers.
K8. Capacity is the hours a user says they can give each week, typed in the first time they open the Action Hub; everything is planned from it, and the plan can lower it later if weeks keep falling short. Effort is how much work each Action Item takes, sized item by item. Together they set how many Action Items fit in a week. Aisha is an example user: capacity 6 hours, 4 Action Items last week, 3 this week.
K9. Calendar sync is optional; users who turn it on set a time range and their sharpest hours.
K10. With sync on, the Action Hub can show the week as a schedule; Mondai finds times in gaps; the user can move times; an Action Item is due by the end of its week, Saturday night, and its time is a suggestion.
K11. A rail on the right of the Action Hub shows the Pathway target (set from capacity, holds steady through an ordinary week), the Pathway pace (updates once a week) and the gap in days.
K12. Rollover: an Action Item still open on Saturday night moves into the next week on its own, so the user never has to decide what to do with it while already behind (asking them would feel like a gate instead of a guide). It takes some of the next week's capacity and pushes the pace later; the target stays.
K13. Buffer flow: finishing the week early opens a screen that offers next week's Action Items to pull forward, the only way to move the pace ahead.
K14. Start of week: the first screen each Sunday, in five versions: Clean slate, Catching up, Rollover (carried items under a magenta tag), Recalibration (when unfinished weeks keep happening, suggests a capacity that fits the hours the user has been giving; take it, set their own or skip it), Reset (after a long absence the week rebuilds from today with progress kept).
