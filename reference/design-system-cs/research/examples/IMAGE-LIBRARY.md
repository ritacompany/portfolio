# CS3 image library: every system image from the twenty case studies

25 Nov 2026. The twenty pages in `../EXAMPLES.md` and `VISUAL-EXAMPLES.md` were opened again in
Chromium and every content image was pulled out on its own: picture files at the size each page
serves them, inline SVG, video frames and, where a page draws its diagram in HTML, a crop of just that
block at double resolution. Each image was judged by looking at it, kept or dropped and filed under
the device names from the catalogue in `VISUAL-STUDY.md`. Research only: no draft, outline or material
file changed.

Private archive, the image library itself: https://claude.ai/artifact/54w7Qi9WrT6CzWdshc9a6T
(private to Chadwick). It groups the images by device under what each device proves, filters by page
and by a UI elements flag and opens every image at full size with its page, author, the caption as
the page gives it, the nearest heading and a link to the live page. The repo is public, so no image or
page text is committed here; this file holds counts and reasons only.

## How the devices were applied

- Every kept image carries one device name from the `VISUAL-STUDY.md` catalogue; no new names were
  added. Colour palettes, ramps, type scales and single component plates are filed as rule plates,
  as the catalogue does for the E-signature foundation plates. Agent output covers screens and replies
  an agent produced from the system (Diorama, WellSky, the MCP audit). Decision table covers the
  catalogue's decisions with the cost written down, including Bupa's triage and approval grids.
- The UI elements flag marks images that show components or their states: buttons, fields, cards,
  alerts, tables and the like, alone, in a matrix or labelled by token. Token tables, number tiles and
  diagrams without a component are not flagged.

## What blocked or needed a workaround

- No page was blocked. Medium (MCP audit, Fortune 200, JW Player, Student Beans) and Design Systems
  Collective (Halstack) all loaded in full on a normal browser load. Medium also fired a background
  call to a Cloudflare check host that did not connect; it did not stop the page loading, and nothing
  was done to get around it.
- Medium's sign up modal covered the code blocks in the MCP audit when they were captured; the modal
  was hidden and the blocks captured again. They turned out to be setup code and were dropped.
- Bupa animates constantly, so element captures timed out on the first two attempts. Its blocks were
  cropped from viewport captures at double resolution instead, with the sticky chapter bar hidden.
  One block (a set of problem summary cards) still timed out; it is a text block and would have been
  dropped either way.
- Limbo Citi: one embedded video showed a connection security message in place of the video, and a
  second embed showed only a logo poster. Both are recorded as drops. Anorbank: the embedded Figma
  prototype showed only its cover, as in the earlier study.
- IndiGo draws its four phase timeline as plain HTML without a panel, which the automatic block
  finder missed; it was found from a full page look and captured by hand. The rest of IndiGo's system
  story is text.
- The MCP audit has two images that show the system (both are Claude replies about the library);
  its before and after structure is in the text, not an image.
- E-signature shows its hero image twice; the second copy is dropped as a duplicate.

## How it was checked

Gates were written before the work and are kept with the scratch scripts, not committed, because only
this file goes in the repo. Results:

- Every one of the twenty pages has an extraction record with candidates saved (checker exit 0).
- Every candidate was judged from the image on a contact sheet, page by page; every kept image has a
  page, author, device from the catalogue vocabulary, note, UI flag and a file that opens as an image
  (checker exit 0; a planted bad device name and a blank note both made it fail, as they should).
- The counts in this file are generated from the catalogue and checked against it.
- The library page was opened in Chromium at 390 and 1280 px: no sideways scroll, filters and the UI
  flag change the counts, an image opens at full size, arrow keys move through images, no script
  errors; the tool defaults check passed.
- Not done: no independent agent rechecked the classification. The device and UI calls are one
  reader's judgment from the images.
