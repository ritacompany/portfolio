Colour · Version A · T3I

the audit as the method. Told in the order the work happened: count, rule, write the rules down, clean the pickers, then the test.

Covers: P1, P2, P3, P4, P5, P6, P7, P8

Colour

Across the screens, the green used for labels and numbers came in five different shades, and the outlines around cards came in four greys.

Before deciding which colours to keep, I wanted to know how each one was actually being used. I grouped every colour in the library (3,555 paints) and roughly 40,000 more on the MVP screens by the job it was doing, such as a label, a card outline or a selected state. Each job then got one token, which is essentially a named colour, set to the shade the screens were already using most for that job.

The colour picker was the other problem. Raw values, the unnamed shades underneath the roles, made up 65% to 78% of every picker, meaning a designer or an agent choosing a colour mostly saw shades with no job attached, and I found it confusing to use myself. I removed the raw values from the pickers so only roles show up, and renamed three roles after what they actually paint. For example, Text/Placeholder became Text/Meta, since only 2 of its 213 layers were placeholders and the rest were times, dates and inactive labels. No layer changed colour, whereas moving to a leaner public palette like Radix or Material 3 would have recoloured the screens.

Gold was never part of the system. It had no value and no variable, and it only kept appearing because it had been written down and then repeated. The product is also dark only, with one mode, so developers set up a single theme and nothing waits on a light one.

When fresh agents later rebuilt a known screen using only the library, every colour they placed was on a published role. The one they got wrong was Text/Display, the brightest text colour, which they mostly skipped for names and titles because the name reads like a type size.

Colour · Version B · T2I

the rejected option first. The tempting fix was to merge colours that share a value; the section argues against it, then shows what judging by purpose produced and how it was tested.

Covers: P1, P2, P3, P4, P5, P6, P7, P8

Colour

Cards, fields and buttons all had outlines in a handful of greys, and because some of them shared the same value it was hard to tell which ones were actually doing the same job.

The quickest fix would have been to merge every colour that shares a value into one token, but a button and a field both have outlines and they are still doing different jobs. So I compared every element by what it does and how it is used.

I started by grouping the library's 3,555 paints and roughly 40,000 on the MVP screens by job, and gave each job one token set to the shade the screens were already using most for it. From there I went through 11 sheets, one kind of element each. Accent text alone had been spread across five greens, and moving it to one changed 551 layers, with six put back because pathway progress is a different job.

Some of these I wrote as simple rules so they don't depend on someone's eye. For instance, an icon always sits one step darker than the text beside it.

Card outlines came in four greys. I gave cards the grey the navigation already uses and gave raised areas inside a card a slightly lighter one, while states keep their own treatment, so a completed item stays darker on purpose.

The colour picker had a similar problem. Raw values, the unnamed shades underneath the roles, made up 65% to 78% of every picker, and I found it confusing to use myself. I took them out of the pickers so designers and agents only see roles, and renamed three roles after what they paint without any layer changing colour. A leaner public palette like Radix or Material 3 would have recoloured the screens.

When fresh agents later rebuilt a known screen using only the library, every colour they placed sat on a published role. They mostly skipped Text/Display, the brightest text colour, for names and titles, since the name reads more like a type size.

Gold was never part of the system. It had no value and no variable and only kept appearing because it was written down and repeated. The product is dark only, with one mode, so nothing is waiting on a light theme.
