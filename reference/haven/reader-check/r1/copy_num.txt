VERSION V1: Hero
V1.S1 Designed as a way for LGBTQIA+ youth to gain access to affirming environments.
V1.S2 For many LGBTQIA+ teenagers, finding a sense of belonging and acceptance can be a difficult and isolating experience.
V1.S3 The lack of affirming environments at home and in their communities is linked to a higher risk of suicide.
V1.S4 This project was developed as part of a UX bootcamp.
V1.S5 The brief was to create a functional product for a specific user group and include a way to connect users with an expert, which Haven calls a Confidante.
V1.S6 If a disapproving guardian or peer found Haven on a user’s phone, it could out them, so privacy drives many of the decisions that follow.

  (label) Demographic access

  (label) 3 Subject matter experts
  (label) 3 LGBTQIA+ college students
  (label) 6 Total interviews
  (label) 5 key insights
  (label) Insight 1, Humanizing experts
V3.S3 When choosing between experts, users look for what makes each one feel human.
V3.S4 They want to know the expert will understand them.
  (label) Insight 2, Sensitive conversations

  (label) Insight 3, Unique identities

  (label) Insight 4, Scheduling concerns

  (label) Insight 5, Personal security

VERSION V4: Designing an MVP
  (label) Designing an MVP
V4.S1 Because the subject is complicated and sensitive, I planned Haven as an MVP in two phases: identity first, then community.
V4.S2 Identity comes first because Haven matches each user with a Confidante through who they are.
V4.S3 The two phases let me decide which features mattered most now and which could wait until after the MVP.

VERSION V7: The Confidante program
  (label) The Confidante program
V7.S1 The Confidante program is built to adapt to each user’s needs and comfort.
V7.S2 Confidantes support the user in two capacities:
  (label) 01 A community liaison that connects the user to different people and communities.
  (label) 02 A source of support for users who need guidance or someone to talk to.

VERSION V8: Primary identity quiz
  (label) Primary identity quiz
V8.S1 One identity model for every user would flatten the differences that shape their experience, so the quiz matches users on the experiences they pick.
  (label) Tags: Interview insight 1, Interview insight 3, Confidante role 1
V8.S2 The quiz groups prompts into five areas: attraction, gender identity, race and ethnicity, belonging and upbringing.
V8.S3 Confidantes then see a summary of the shared experiences behind each match, so they can tailor support and recommend communities that fit.

VERSION V10: Confidante profile
  (label) Confidante profile
V10.S1 Users need to understand who the Confidante is before making a decision.
V10.S2 They need to feel understood, represented and safe.
  (label) Tags: Interview insight 1, Interview insight 3, Testing insight 4
V10.S3 Shared experiences, differences and humanized bios help users compare Confidantes and decide whom to schedule a chat with.
V10.S4 Testing showed that those details needed more prominence.
V10.S5 I made shared experiences the focus of the page and replaced vertical swiping with suggested Confidantes along the bottom, so users could switch between profiles.

VERSION V11: Scheduling a chat
  (label) Scheduling a chat
V11.S1 Users needed to know what to expect before booking an introductory chat.
V11.S2 Testing showed confusion about how chats would work and how long they would last.
V11.S3 The scheduling screen now explains that they happen by text, last a set 30 minutes and can end early, so users can pick a time when they can be alone.
V11.S4 Your events lists each upcoming chat with the Confidante’s name and time.
  (label) Tags: Interview insight 4, Testing insight 1, Testing insight 2

VERSION V12: Chat-based interactions
  (label) Chat-based interactions
V12.S1 When speaking out loud is not safe or private, the interaction itself has to lower the barrier to asking for support.
  (label) Tags: Interview insight 2
V12.S2 Chats happen by text, not voice or video, so users don’t have to say anything sensitive out loud.
V12.S3 Each chat has a set length and can end early, which leaves users in control of when and how much they share.

VERSION V13: Security features
  (label) Security features
V13.S1 Privacy is a condition for access.
