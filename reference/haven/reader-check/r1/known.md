# What the reader already knows, per version (Haven, round 1, 9 Nov)

Built from reference/haven/final-copy.md with every proposal applied, page in order. Version n is block n of the
page. Fact Kn is what block n tells the reader, so it is known only to versions after n (K1 to V2 onward, K2 to V3
onward, and so on). V1 knows nothing. V15 is not on the page and knows K1 to K14. When judging a version, use only
the facts with a lower number. Every solution block sits beside its own screen, which the reader also sees.

K1 (known to V2 onward). Haven was designed so LGBTQIA+ youth can reach affirming environments. Many LGBTQIA+ teenagers find belonging hard, and lacking affirming environments at home and in their communities is linked to a higher risk of suicide. It was a UX bootcamp project; the brief asked for a product for one user group with a way to connect users with an expert, which Haven calls a Confidante. If a disapproving guardian or peer found Haven on a user's phone it could out them, so privacy drives many decisions.
K2 (known to V3 onward). The Trevor Project found LGBTQ youth with at least one affirming space had 35% lower odds of a suicide attempt, and those with an affirming adult at home were 40% less likely to attempt suicide.
K3 (known to V4 onward). Minors need a guardian's consent to join a study, and asking would out them, so the designer interviewed two proxy groups: 3 subject matter experts and 3 LGBTQIA+ college students, 6 interviews. Five interview insights: 1, users want experts who feel human and will understand them; 2, users are uncomfortable discussing identity aloud where someone could overhear; 3, a one size fits all identity model could flatten the differences in each user's experience; 4, users need a time when they can be alone and feel safe talking to an expert; 5, users worry disapproving guardians or peers may find out they use an LGBTQIA+ product.
K4 (known to V5 onward). Haven was planned as an MVP in two phases, identity first and community second, because Haven matches each user with a Confidante through who they are; the phases decided which features came now and which waited.
K5 (known to V6 onward). The first wireframes had a chat length to pick, a passcode as the only security and top matches to swipe through; testing changed all three.
K6 (known to V7 onward). Six participants tested three flows (match enrollment, selecting a Confidante, scheduling a chat). Testing insights: 1, users were unsure how they would talk to the expert; 2, the duration section of scheduling confused them; 3, the design lacked enough security features; 4, users wanted to know more about each Confidante before choosing. Each solution block is tagged with the insights that shaped it.
K7 (known to V8 onward). The Confidante program adapts to each user's needs and comfort; a Confidante is a community liaison connecting the user to people and communities, and a source of support.
K8 (known to V9 onward). One identity model would flatten differences, so the quiz matches users on the experiences they pick, in five areas (attraction, gender identity, race and ethnicity, belonging, upbringing); Confidantes see a summary of the shared experiences behind each match to tailor support and recommend communities.
K9 (known to V10 onward). The early flow had users choose a Confidante before an introductory chat; testers hesitated, went back and forth between profiles and undid choices, so selection moved after the introductory chat, and users can chat with more than one Confidante before choosing.
K10 (known to V11 onward). Users need to understand who a Confidante is before deciding; the profile leads with shared experiences, differences and humanized bios, and suggested Confidantes along the bottom replaced vertical swiping so users can switch profiles.
K11 (known to V12 onward). Testing showed confusion about how chats work and how long they last; the scheduling screen explains chats happen by text, last a set 30 minutes and can end early, so users can pick a time when they can be alone. Your events lists each upcoming chat.
K12 (known to V13 onward). Chats are by text, not voice or video, so users never say sensitive things aloud; a set length that can end early leaves users in control of how much they share.
K13 (known to V14 onward). Privacy is a condition for access; users need safeguards before, during and after a conversation. The screens show a security PIN with Face ID and a discreet setup (disguise icon, hidden in the app switcher, notifications off).
K14 (known to V15 only). The first MVP phase was built around being understood and being safe; identity was the first phase and community is the next.
