# Move judgment out of the drafting session

The fix is not better rules or more skills. It is taking three jobs away from the session that writes the draft: remembering the process, enforcing the mechanical rules and grading its own work. Each job goes to something that cannot forget or flatter itself. A JSON state file plus hooks owns the order of the seven steps. Deterministic scripts own every rule a pattern can check. Separate read-only subagents with fixed inputs own claim checking and the stranger read. A small workflow script runs the non-interactive stretch from draft to review packet, so the voice pass happens because code calls it, not because a session remembered. Anthropic's own documentation says plainly that CLAUDE.md and injected rules are advisory while hooks are deterministic, and that a bloated rule file is the usual reason a rule gets ignored. That makes the current pattern of adding a rule after each failure the cause of the next failure, not its cure. The external resources worth using are few and mostly patterns to borrow rather than things to install: Anthropic's doc-coauthoring reader test, the code-review plugin's independent scorer with a hard cutoff, obra/superpowers' verification-before-completion and the already-installed humanizer. On the human side, ghostwriters and magazine checkers reach reliability through role separation and early approval of small artifacts, which suits an owner who talks better than he writes rules. About a third of the always-loaded rule text can be deleted outright once the mechanisms exist. Throughout, **(sourced)** marks a finding from the cited source and **(inference)** marks a conclusion drawn from the sources or from reading this repo.

## Today's loop asks one session to be the process, the critic and the memory

Reading the repo shows where the weight sits. Every turn, a `UserPromptSubmit` hook injects the 47 lines of `.claude/portfolio-rules.md`, on top of the project `CLAUDE.md` (86 lines), the global `CLAUDE.md`, the 300 line `reference/cs2/CS2_PROCESS.md` that each session is told to read first and `.claude/case-study-rules.md`. The seven step loop lives in prose in that process doc. The only structural pieces are the hooks: `archive-guard.sh` blocks writes to the verbatim evidence files before they happen, and `copy-check.sh` catches dashes. Everything else, including step 4's "Run humanizer, then no-ai-slop", depends on the drafting session choosing to do it **(inference, from the repo files)**.

The research explains why that fails. Anthropic's memory docs say CLAUDE.md content is "context, not enforced configuration", recommend under 200 lines per file and warn that "if two instructions contradict each other, Claude may pick one arbitrarily" ([Claude Code memory docs](https://code.claude.com/docs/en/memory)) **(sourced)**. The best practices page is blunter: "If Claude keeps doing something you don't want despite having a rule against it, the file is probably too long and the rule is getting lost," and "If you emphasize many lines, none of them stands out" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)) **(sourced)**. Instruction-following benchmarks put the reliable ceiling at **about three simultaneous constraints**, with GPT-4's full-compliance rate falling from 84.7% at one constraint to 61.9% at five ([Jiang et al. 2023](https://arxiv.org/html/2310.20410)) **(sourced)**, and every top model performs **39% worse across multi-turn sessions** than in single turns ([Laban et al. 2025](https://arxiv.org/abs/2505.06120)) **(sourced)**. A long talking session followed by a draft is the worst case on both counts.

Two concrete contradictions in the current files show the cost. The injected rules still demand a "CREATIVE LEVEL" at the top of every reply, while `CS2_PROCESS.md` says that system was retired on 24 Sep and does not apply. The session is told both things every turn **(inference, from the repo files)**. And `copy-check.sh` is registered as a `PostToolUse` hook. The docs state a PostToolUse hook "can't undo actions since the tool has already executed" and that `decision: "block"` there only adds a reason next to the result ([Hooks guide](https://code.claude.com/docs/en/hooks-guide); [Hooks reference](https://code.claude.com/docs/en/hooks)) **(sourced)**. So the dash check lets the dash land and then asks for a fix. It is a nudge, not a wall **(inference)**.

The failure the owner describes, a session judging its own work, is the one the literature is clearest on. Model judges recognize their own text and favor it in proportion ([Panickssery et al. 2024](https://arxiv.org/abs/2404.13076)), and self-refinement amplifies that self-bias across six model families ([Xu et al. 2024](https://arxiv.org/abs/2402.11436)) **(sourced)**. Anthropic's own framing of the fix: "A reviewer running in a fresh subagent context sees only the diff and the criteria you give it, not the reasoning that produced the change" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)) **(sourced)**.

## Seven mechanisms replace most of the 84 rule lines

The professional analogues all point the same way. Magazine fact checkers "inherit" the writer's reporting file and tick off each claim against it. They do not edit prose or judge voice ([CJR, How fact-checking and reporting mix](https://www.cjr.org/the_delacorte_lectures/how-fact-checking-and-reporting-mix.php)) **(sourced)**. Shingo's mistake-proofing moves detection to the step where the error is made and makes it "obvious at a glance" rather than relying on end-of-line inspection ([mistakeproofing.com](https://mistakeproofing.com/a-brief-tutorial-on-mistake-proofing-poka-yoke-and-zqc/)) **(sourced)**. Gawande's checklists work only when short, tied to a named pause point and limited to killer items. His surgical team deliberately cut items for rare events ([Steve Grossi on The Checklist Manifesto](https://www.stevegrossi.com/on/the-checklist-manifesto)) **(sourced)**. Appending a rule after every failure breaks all three principles at once: it lengthens the list, has no pause point and treats every past failure as a killer item **(inference)**. The mechanisms below are the repo-level equivalents.

### Roles: one pass, one job, one input

Split the loop into roles that never share a context. The drafter is the main session, and it only talks and drafts. The copy desk is code: hooks and a lint script. The checker is a subagent that gets the draft path and the `reference/` files and returns one verdict per claim. The stranger is a subagent that gets only the draft and must answer questions a cold reader would ask. Chadwick is the principal. He judges voice, substance and the decisions shown. Nothing a script or checker can catch should reach him **(inference, modelled on the CJR checker account and the Bush White House Staff Secretary, who consolidated changes so the principal saw clean drafts, [George W. Bush Library](https://georgewbushlibrary.gov/topics/speeches))**. The speechwriting record adds a priority: a Johnson speechwriter said the job is knowing what the president thinks, not how he sounds ([Christian Science Monitor, 1997](https://csmonitor.com/1997/0204/020497.us.us.1.html)) **(sourced)**. Substance drift, claims Chadwick would not make, is the bigger risk than surface style, which argues for spending the checker's effort on claims first **(inference)**.

### Separate agents with fixed inputs

Custom subagents are Markdown files in `.claude/agents/` with YAML frontmatter. Each runs in its own context, "doesn't see your conversation history... or the files Claude has already read" and can be pinned to a tool list and model; `omitClaudeMd: true` keeps the project rules out ([Subagents docs](https://code.claude.com/docs/en/sub-agents)) **(sourced)**. Two agents cover the gap. `claim-checker` gets `tools: Read, Grep, Glob`, `omitClaudeMd: true` and a different model from the drafting session. It returns a table of claim, source path, verdict (traced, partly traced, not traced) and evidence tag. That operationalizes the existing CONFIRMED, ESTIMATE, ASSUMED, INVENTED and PARAPHRASE marks as the checker's tick per claim. Draft-blind checking matters here. In Chain-of-Verification, answering each verification question in a separate prompt without the draft scored 63.7 FactScore against 60.8 when the draft was visible, and 71.4 with an added cross-check ([Dhuliawala et al. 2023](https://arxiv.org/html/2309.11495)) **(sourced)**. `stranger-reader` follows Anthropic's doc-coauthoring Reader Testing stage. It predicts 5 to 10 reader questions and sends each to a sub-agent that "receives only the document and the question", then loops until the fresh reader answers correctly ([doc-coauthoring SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/doc-coauthoring/SKILL.md)) **(sourced)**. That is the "write for the stranger" standard turned into a test.

The known leak is the delegation message. The main session writes it and can paraphrase its own justification into it, and no doc guarantees otherwise ([Subagents docs](https://code.claude.com/docs/en/sub-agents)) **(sourced gap)**. The fix is to have the agents read file paths themselves and to send the delegation from a script with fixed text, not from the session **(inference)**. Reviewers also manufacture findings: "A reviewer prompted to find gaps will usually report some, even when the work is sound" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)) **(sourced)**. Anthropic's code-review plugin handles this with an independent scorer per finding on 0 to 100. It filters anything under 80 and excludes "General quality concerns not covered by CLAUDE.md" ([code-review README](https://raw.githubusercontent.com/anthropics/claude-code/main/plugins/code-review/README.md)) **(sourced)**. Copying that rule, so a finding must cite a written rule or a reference file or it is dropped, enforces Chadwick's "never manufacture criticism" standard mechanically **(inference)**.

### Hooks as gates, not reminders

Hooks are "deterministic and guarantee the action happens" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)), and a `PreToolUse` deny "blocks the tool even in `bypassPermissions` mode" ([Hooks guide](https://code.claude.com/docs/en/hooks-guide)) **(sourced)**. Three hooks carry the process. First, move `copy-check.sh` from `PostToolUse` to `PreToolUse` on `Edit|Write`, exiting 2 with the offending lines on stderr, so a dash never reaches the file **(inference from the documented event semantics)**. Second, add a `PreToolUse` gate on the state file (next subsection) that allows only the next legal step and only when the current step's artifact exists **(inference; no published Anthropic recipe for this exists, it is composed from documented primitives)**. Third, add a `Stop` hook that reads the state file and blocks ending the turn only when a step is open and its artifact is missing. It must exit early on `stop_hook_active`, because Stop fires on every reply and Claude Code overrides the block after eight consecutive continuations ([Hooks reference](https://code.claude.com/docs/en/hooks)) **(sourced mechanics; the design is inference)**. Prompt and agent hook types exist, but they reintroduce model judgment, and agent hooks are marked experimental ([Hooks reference](https://code.claude.com/docs/en/hooks)) **(sourced)**. Keep gates as command hooks reading files.

For mechanically checkable copy rules, extend the same script: an Oxford comma pattern, curly and straight quotation marks in CS2 copy (his "no quotes in CS2" rule), a colleague name denylist and an unmarked number check. Regex will false-positive on product nouns that double as names, so names and numbers should warn rather than block **(inference, carried from the earlier research)**.

### A state file instead of a status table in prose

Anthropic's long-running harness uses a JSON feature list where "Coding agents change only the `passes` status", because "the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files". It names "marking features done without testing" and declaring victory early as the failure modes ([Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)) **(sourced)**. The portfolio's status table and "Where section N stopped" lists are the same thing in the weaker format. A `reference/cs2/state.json` holds one entry per section with a `step` field (open, talk, draft, voice, layout, review, save) and the artifact path each step must produce. The PreToolUse gate enforces transitions. A `SessionStart` hook prints the current section, step and missing artifact. The docs advise phrasing injected context "as factual statements, not imperative instructions" ([Hooks reference](https://code.claude.com/docs/en/hooks)) **(sourced)**, so it reads "Section 3. Step: talk. Required artifact missing: talk notes." That one line replaces the "start here, read this file, then the table" preamble **(inference)**.

### Artifacts at every pause point

Each step should leave a file a person can look at, because an artifact makes incompleteness visible at a glance in the way a checker's ticks do **(inference from the CJR and Shingo sources)**. The set is small. Talk notes come first, then the draft. A voice report holds humanizer's marked tells and the no-ai-slop detect output. A claim ledger comes from the checker, the stranger Q and A from the reader agent and the beat list from step 5, which already exists. Last is a review record with Chadwick's verdict and a one-line reason. The state gate checks for the file, not for its quality. Quality stays with the agents and Chadwick. Hooks enforce that a step happened, not that it was done well. The skills research makes the same point about hookify ([hookify README](https://raw.githubusercontent.com/anthropics/claude-code/main/plugins/hookify/README.md)) **(sourced limitation)**.

### A workflow script for the stretch nobody talks through

Claude Code workflows are JavaScript files in `.claude/workflows/` with `agent()`, `pipeline()` and `parallel()`. "A workflow moves the plan into code," and the script, not the model, decides what runs next. The constraint is "No mid-run user input... For sign-off between stages, run each stage as its own workflow" ([Workflows docs](https://code.claude.com/docs/en/workflows)) **(sourced)**. That constraint maps exactly onto this loop. Talk, beat list approval and review are human stages. Draft, voice pass, lint, claim check and stranger read have no human in them. One `post-draft` workflow runs lint, then humanizer in a fresh agent, then the claim checker and stranger reader in parallel, then writes the review packet. The voice pass stops being skippable because it is a line of code **(inference)**. It also fixes the delegation leak, since the script holds the delegation text. Anthropic's general guidance supports this shape: prompt chaining with "programmatic checks... on any intermediate steps" for fixed sequences, and evaluator-optimizer loops "when we have clear evaluation criteria" ([Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)) **(sourced)**. Cap revision at one or two rounds, since gains concentrate in the first pass and self-bias grows with iteration ([Xu et al. 2024](https://arxiv.org/abs/2402.11436)) **(sourced)**.

### Measurement that counts his verdicts, not the session's

The review record becomes an append-only `reference/cs2/reviews.jsonl`: section, process version, verdict, one-line reason. That log is the only honest source of a reliability number. Clearing 90% at 95% confidence takes about 29 consecutive acceptances on a frozen process. Two of two accepted proves only a 22% floor, a figure computed from the exact binomial per [NIST/SEMATECH](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm) **(sourced method)**. Test the checker by planting known violations in a draft and counting catches, reporting true positive and true negative rates separately rather than raw agreement ([Husain, Using LLM-as-a-Judge](https://hamel.dev/blog/posts/llm-judge/)) **(sourced)**. LLM judges correlate with experts "close to zero" on creative writing quality ([Chakrabarty et al. 2023](https://arxiv.org/html/2309.14556v2)) **(sourced)**, so no judge gets the voice verdict.

### Capture from talk instead of rules from failures

Professional voice work runs interview first, sample second, volume last. Scribe Media delivers a sample chapter "to establish voice and tone" for approval before the manuscript and adds voice checkpoints at early pages and the midpoint ([Scribe business book](https://scribemedia.com/service/business-book-ghostwriter); [Scribe memoir](https://scribemedia.com/service/memoir-writing-services/)) **(sourced, self-reported marketing)**. The client approves voice by recognition on an artifact and never writes a style guide **(inference)**. Ford's speechwriter got a long interview with the president and then studied past speeches ([Ford Library finding aid](https://www.fordlibrarymuseum.gov/digital-research-room/finding-aids/paul-theis-and-robert-orben-files-1974-77)) **(sourced)**. One practitioner blog adds that clients start mimicking "good writing" after the first session, so the earliest recorded talk is the best voice evidence ([River Editor](https://rivereditor.com/blogs/how-ghostwriters-capture-client-voice-first-interview)) **(sourced, single blog)**. Dan Shipper drafts by walking with a voice memo running, and Every's guide separates dictation for when you know what to say from live voice conversation for questions and real-time correction ([Behind the Craft](https://creatoreconomy.so/p/how-to-use-ai-to-write-dan-shipper); [Every, Build faster with voice](https://every.to/guides/build-faster-with-voice)) **(sourced)**. No primary source was found on AI as interviewer **(sourced gap)**.

For Chadwick this means three changes **(inference)**. First, the talk step produces talk notes in his phrasing, and the draft is built from them with his sentences preserved where possible. That respects the position Simon Willison endorses that "no rewrite is lossless" ([Willison, Aug 2026](https://simonwillison.net/2026/aug/11/there-are-no-lossless-transformations-of-natural-language-text)) **(sourced)**. Second, he approves a short sample, one beat in full prose, before the session drafts the whole section. That extends the beat list gate he already has from structure to voice. Third, each rejection is triaged instead of appended. Distilled learned rules cut edit distance about 73% against no learning, but simply showing past edits did no better than nothing, and handing over the true preference was **more than four times better than the best learned rules** ([Gao et al. 2024, PRELUDE](https://arxiv.org/html/2404.15269v3)) **(sourced)**. Examples plus rules beat examples alone by about 9% ([PROSE](https://arxiv.org/html/2505.23815v1)) **(sourced)**. So the triage order is: make it a hook if code can check it. Otherwise add the approved passage to an examples file if it is voice. Otherwise, as a last resort, make it one reasoned line in the reviewer's rubric with a source. `docs/VOICE.md` gets written from the clustered one-line reasons in `reviews.jsonl`, in his words, after a grading round. People discover their criteria by grading real outputs ([Shankar et al. 2024](https://arxiv.org/abs/2404.12272)) **(sourced)**. A premortem before each section ("he rejected this draft; why?"), seeded from that log, turns past failures into predictions for this section rather than standing rules ([HBR, Performing a Project Premortem](https://hbr.org/2007/09/performing-a-project-premortem)) **(sourced method; application is inference)**.

One constraint from the repo shapes capture. `CS2_PROCESS.md` says Mondai source material, including transcripts, chats and anything quoting them, never goes into git and stays under `~/Documents/CS2-research/`. Talk notes from a CS2 session quote him about Mondai, so they belong there with only a pointer in `state.json`. The state gate must check that path outside the repo **(inference, from the repo files)**.

### Build order inside the repo

A sequence that delivers value at each stage **(inference)**. Stage one, under a day: do the deletions above, move `copy-check.sh` to `PreToolUse` and extend it, create `reference/cs2/state.json` from the current status table and add the SessionStart line and the transition gate. Stage two: write `.claude/agents/claim-checker.md` and `.claude/agents/stranger-reader.md` with read-only tools, `omitClaudeMd: true` and a different model from the drafter. Then add `.claude/workflows/post-draft.js`, which runs lint, humanizer, checker and reader and writes the review packet path into the state file. Chadwick reads both agent files before first use. Stage three, running alongside the work: log every verdict in `reviews.jsonl`, plant violations in one draft to measure the checker's catch rate, then write `docs/VOICE.md` from the clustered reasons once roughly ten sections have been graded. Only after that is the process frozen and acceptances counted.

## Conclusion

The repo already proves the thesis in miniature. The two rules that never break, the verbatim evidence files and dashes, are the two enforced by code. Every rule that breaks lives in prose the drafting session is trusted to remember. The useful reframe is that a rule file is a symptom ledger. Each line records a failure the system had no mechanism to prevent, so the response to a new failure is to ask which mechanism was missing, not which sentence was. That also changes what Chadwick's time is for. Once a script owns the copy rules, a checker owns the claims and a cold reader owns comprehension, his reviews stop being spent on catchable errors. They concentrate on the only things he can judge: whether the decisions shown are the right ones and whether it sounds like him.

Two things remain unproven. No source measures whether hooks plus separate judges actually reduce rule-breaking in writing sessions, and LLM judges have not been shown to agree with an expert editor on long-form prose. So the build has to carry its own evidence. The verdict log and the planted-violation test are not overhead on the system. They are how anyone will know whether it works, and the first ten logged reasons are also the raw material for the voice document the repo has deliberately left empty.
