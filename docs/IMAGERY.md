# Portfolio imagery direction

Working record. Started 2026-08-31 from a ChatGPT brainstorm moved into this repo.
Nothing here is approved. This is the thinking, the shortlist and the open decision.

## The job

Portfolio imagery that communicates systems thinking. Not decoration, not stock abstract
render. The image has to carry the claim, because a portfolio that says "systems thinker"
in copy and shows nothing systemic is making an unsupported claim.

## What was explored and rejected

The first pass was built around building blocks. Translucent Lego with visible internals,
magnetic tiles, molecular models, letterpress type, modular vessels.

All of them fail the same way. They put the meaning inside the object. The viewer looks at
one beautiful block instead of at the relationships between blocks. Systems thinking is
about relationships, so an object that rewards close inspection of itself is arguing
against the point it is meant to make.

Kept in reserve, not dead: nested objects where each interior is a different kind of thing,
geological core sample where internal strata record history. Both say something the main
direction does not, which is that systems accumulate history.

## The direction

Two ideas survived, and they turned out to be the same idea.

A kinetic mobile and an invisible magnetic field are both: a repeated unit, plus an
invisible force that determines its arrangement. Gravity or magnetism, same grammar. The
meaning sits between the objects rather than inside them.

### Two rules this imposes

1. Make the unit boring. If the unit is beautiful or strange the image becomes about the
   object and it fails the same way the blocks did. A plain repeated unit leaves the eye
   nothing to look at except relationships.
2. The unit needs an axis. A field expresses itself as orientation. A sphere in a magnetic
   field is just a sphere. This is mechanical and it rules out most candidates.

## Subject candidates

| Subject | Says | Fails by |
| --- | --- | --- |
| Plain card, identical flat slabs | UI without being a screenshot | Reading as Trello, cards are a cliche |
| Needle, rod, pill, chevron | Purest field read, orientation is instant | Compass imagery reads strategy consultancy |
| Thread, continuous filaments deflected | The connection is the subject, not the node | Becoming flow line wallpaper |
| Own components stripped to grey volumes | Unfakeable, nobody else's field is made of this work | Too legible it is a screenshot, too abstract it needs a caption |
| Person token, abstract unit standing for a user | Connects to human centered design | Sentimental, or reads as an org chart |
| The absence, only the effect shown | Conceptually strongest, forces are invisible | Illegible without copy carrying it |

### Current recommendation

A slab with a face. Real components from the work, extruded to thin grey slabs, color and
labels removed, rotated by the field.

A slab is a card and a needle at once, so it satisfies the axis constraint and the UI read
at the same time. Because the silhouettes come from actual work, the imagery cannot be
reproduced by anyone else running the same setup.

## The mobile and the field are not interchangeable

A still image of a mobile cannot show propagation. Mobiles communicate by moving. A photo
of one is a photo of some shapes hanging. Mobile means motion or it means nothing.

The mobile shows the dependencies. The field shows only the consequences. The mobile puts
the structure on screen. The field hides the structure entirely, which is conceptually
purer and visually much quieter.

That difference assigns them rather than forcing a single choice.

- Field for CS1, the operation. Invisible coordination shaping visible behaviour.
- Mobile for CS3, the design system. Visible structure, one change propagating.
  PROPOSAL ONLY. CS3 source material not yet reviewed.
- CS2, the framework, wants a third force. Probably time, since it owns the Growth Journey
  and weekly scheduling. Same unit, sequence rather than attraction.

Same unit across all three, different force each time. The imagery becomes a system, which
is itself the argument. Worth more than any single hero image.

## Production

Ranked by what to do first, not by final quality.

1. Code prototype. Canvas or three.js, roughly an afternoon. Answers the only question that
   matters, which is whether this reads as a system or as decoration. Do not model or
   fabricate anything before this.
2. Live on the page. A hero where the cursor perturbs the field demonstrates propagation
   instead of depicting it. A product designer can build this. A photographer cannot.
3. Blender geometry nodes for final stills, once the code prototype has proven the read.
   Scatter instances, orient by a vector field. Roughly a weekend to learn.
4. Physical fabrication, iron filings, ferrofluid. Rejected. Months of work, low control,
   and ferrofluid is thoroughly played out.

## Known risk

Abstract 3D render heroes are common in portfolios right now. Two things defeat that and
both are available here. Units derived from real components, and motion that shows
propagation rather than implying it.
